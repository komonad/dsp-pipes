# 性能测量

> 本文档同时提供[英文版](PERFORMANCE.en.md)。

本 Unity 运行时中的分配计数器对一次已知的 32 KiB 托管分配返回零。当前检查用该校准结果将计数器判定为不可用。下文历史读数中的零字节数据来自该计数器。分配测量需要可用的计数器；实际货物计数另行检查。

## 每节管道十单位容量，0.6.2

每个管道节点贡献 10 单位。在连接 10,000 单位储液罐的 100,000 个节点上，原生运行时 I/O 提供 1,010,000 单位的共享容量。三次各含 200,000 次存入/提取对的采样测得每次操作中位数 322.6 ns，拓扑访问为零，库存与增产点守恒。另一项在 100,000 个节点上运行的 10,000 个分拣器负载平均每 tick 为 1.098 ms，240 tick 内 p95 为 2.875 ms，最大值为 3.444 ms。这些测量不含帧渲染。

独立百万节点图的每次操作中位数为 135.5 ns。历史容量存档检查在拆分、合并、提取与序列化过程中保留超出容量的库存与增产点，并执行新的准入上限。

原生检查渲染一个选中节点和两个或四个直接相邻节点，分别经过绿色与青色两个绘制阶段。稳定检查在跨帧时保留缓存的描边几何。测试插件在启动时与每次更新时静音 Unity 音频。

## API 与可配置运输，0.4.0

原生运行时回归套件以零失败完成，覆盖导出的 API 文档、重叠物品发放、配置排除、撤销后保留库存、原生固体存入/提取、部分接受、物流塔共享与原生储液罐限制。

| 负载 | 结果 |
| --- | ---: |
| 原生工厂 I/O，10 个节点 | 每次操作中位数 148.9 ns |
| 原生工厂 I/O，1,000 个节点 | 每次操作中位数 152.1 ns |
| 原生工厂 I/O，100,000 个节点 | 每次操作中位数 196.8 ns |
| 原生共享 I/O，100,000 个节点与一个储液罐 | 每次操作中位数 319.3 ns |
| 10,000 个原生分拣器，100,000 个管道节点，240 tick | 平均 0.952 ms/tick；p95 为 2.170 ms |
| 独立 .NET 8 图 I/O，1,000,000 个节点 | 每次操作中位数 123.3 ns |

原生各行测量经过补丁的工厂存储调用与分拣器模拟；独立一行测量 .NET 8 上的图操作。帧渲染与公共 API 门面开销需要单独的负载。稳定 I/O 的拓扑访问为零。Unity 分配计数器仍不可用。原生沙盒重载夹具同样在 60 塑料/分钟下保持产量，产出库存增量为零。

## 共享流体空间与建造，0.3.0

0.3.6 版本还使用真实风力发电机与电力覆盖验证原生电网集成。在发电容量分别为 0、834 和 3334 J/tick 时，1667 J/tick 的阀门需求每秒分别传输 0、30 和 60 单位。关闭的阀门请求零能量。恢复供电会补上阀门缺失的原生用电端，并保留其电力覆盖。阀门 tick 会访问按工厂缓存的阀门列表，其中包含管道已断开的阀门。

在一个复制出的 233 节点工厂存档上，原生悬停/预览处理器与生产渲染器给出以下 CPU 测量结果。每个模式都会恢复其初始连接与 mod 库存，并预热网格。这些测量不含 GPU 执行与硬件鼠标射线检测。

| 操作 | 0.2.6 中位数/最大值 | 0.3.0 中位数/最大值 |
| --- | ---: | ---: |
| 建造悬停 | 0.599 / 2.793 ms | 0.022 / 2.380 ms |
| 移动建造路径预览 | 0.705 / 3.801 ms | 0.032 / 3.251 ms |
| 拆除悬停 | 0.007 / 3.348 ms | 0.008 / 3.570 ms |

两次原生九节点待建放置分别耗时 0.081 和 0.274 ms，调用期间零次第 2 代垃圾回收。管道建造使用原生点预览，垃圾回收调度交由运行时处理。在复制的 233 节点场景中带绘制执行实际拆除，中位数为 5.178 ms，最大值为 83.801 ms。接头与空间区块网格重建会造成偶发的拆除尖峰。

在连接 10,000 单位储液罐的 100,000 节点网络上，原生管道存入/提取操作的每次操作中位开销为 302.1 ns。测试执行三次各含 200,000 次存入/提取对的采样，并在拓扑访问为零的前提下校验库存/增产点守恒。共享容量为 10,010,000 单位。所测负载由存储访问调用组成。另一项在 100,000 个管道节点上的 10,000 分拣器夹具平均每 tick 为 1.037 ms，240 tick 内第 95 百分位为 2.479 ms，最大值为 4.324 ms。

覆盖范围包括等百分比储液罐堆叠与物流塔插槽、重复接口的容量只计一次、独立管道连通分量之间的存储桥接、物流塔输入的过滤绑定、超出本地管道/物流塔份额的提取、本地份额为空时的普通储液罐输出、隔离清空、容器移除/退还、存档恢复、双侧阀门隔离、小数速率限制、逆流拒绝、两种液位目标以及不兼容流体拒绝。加载的游戏内夹具调用原生检查与 uGUI 按钮回调。原生放置夹具接受带活动连通管道碰撞体的八度分支，同时保留对固体建筑的拒绝。

原始测量数据：`runtime-results.txt`、`interaction-results.txt` 与 `screenshots/ingame/gameplay-results.txt`。

## 历史运输测量，0.2.3

测量于 2026-10-21，对象为 FluidPipes 0.2.3，硬件为 AMD Ryzen 7 9800X3D，系统 Windows x64。游戏：Dyson Sphere Program 0.10.35.29151，Unity 2022.3.62，Mono CLR 4.0.30319.42000。Release 构建，BepInEx 5.4.17、CommonAPI 1.6.7、LDBTool 3.0.3、DSPModSave 1.2.2。

## 原生工厂 I/O

基准运行经过补丁的原版 `PlanetFactory.InsertInto` 与 `PickFrom` 方法。每个采样在 10,000 次预热对之后执行 200,000 次存入/取出对。端点 ID 在整个连通分量内按确定性方式变化。表中给出五次采样的中位数；一次操作是存入或取出之一。分配计数器覆盖调用线程上的循环，不含测量/报告构建。

| 管道节点 | 每次操作中位数 | 实测采样范围 | 200 万次操作的分配字节数 |
| ---: | ---: | ---: | ---: |
| 10 | 91.3 ns | 90.8–91.8 ns | 0 |
| 1,000 | 93.1 ns | 92.9–93.3 ns | 0 |
| 100,000 | 139.6 ns | 136.2–147.4 ns | 0 |

每次运行都断言稳定 I/O 期间拓扑访问为零，且最终库存为空。更大的连通分量会增加内存/缓存开销，而操作次数与连通分量规模无关。

## 分拣器负载

10,000 个原版 `InserterComponent.InternalUpdate` 状态机在共享的 100,000 节点连通分量上运行 240 tick。移动耗时为 10,000 内部单位，每次拾取一个物品；半数分拣器启用原生堆叠存入路径。所有分拣器同相位启动。每个 tick 校验整个网络的库存与增产点总量，以及分拣器持有的物品。

| 每个模拟 tick 的 CPU 时间 | 测量值 |
| --- | ---: |
| 平均值 | 0.619 ms |
| 第 95 百分位 | 1.429 ms |
| 最大值 | 1.626 ms |

计时区段由分拣器状态机与管道存储调用组成。电力模拟、放置、星球渲染、其他工厂系统与守恒检查在该区段之外运行。帧时间评估需要覆盖完整帧的测量。

## 拓扑与争用

这些运输参考测量使用 0.2.3 版本。0.2.5 版本新增节点几何缓存，以及拓扑访问次数恒定的叶节点切割与移除。

Unity/Mono 核心套件在移除 100,000 节点链的中间边后用 20.53 ms 重建该链。该数值不含原生几何/路径变更。反复的大规模断开与拆除可能超出单帧预算，因为它们会重复遍历并重新划分受影响的连通分量。

在一个共享的 100,000 节点库存上，Unity/Mono 核心基准在单工作线程下达到 1926.2 万次操作/秒，四线程下 1033.0 万次，八线程下 784.0 万次。工作线程在共享库存锁上争用，使该负载下吞吐随线程数增加而下降。数量与增产点保持守恒。

独立 .NET 8 套件另外测试了一个 1,000,000 节点连通分量：增量构建 452.82 ms，每次存储操作中位数 134.6 ns，I/O 期间拓扑访问为零。这些结果反映 .NET 8 执行情况；Unity/Mono 各行反映游戏内执行情况。

## 交互 CPU 测量（0.2.5）

一个保存的 75 节点工厂夹具测量操作确认前的原生拆除悬停、建造悬停与活动路径预览阶段。每个模式恢复相同的初始连接与库存，预热管道网格并采集 20 个采样。计时区段包含处理器、预览、gizmo 与生产管道绘制的 CPU 工作。GPU 执行与完整帧计时需要额外测量。

| 操作 | 0.2.4 中位数/最大值 | 0.2.5 中位数/最大值 |
| --- | ---: | ---: |
| 拆除悬停 | 361.882 / 670.613 ms | 0.004 / 3.470 ms |
| 建造悬停 | 0.167 / 2.345 ms | 0.661 / 4.990 ms |
| 移动建造路径预览 | 0.237 / 3.768 ms | 0.612 / 3.900 ms |

该夹具还通过原版工厂 API 拆除全部 75 个复制的管道实体，并在每次删除后绘制：中位数 1.164 ms，最大值 29.706 ms。每个余下的管道实体都保留原生货运路径；被移除的节点会同时离开两张逻辑图。夹具在源存档数据的内存副本上操作。

一个带高度差的 16 节点环分两批放置，使用回收的待建 ID 与反向完成顺序。环上每个节点都恰好保留其两个相邻节点与互惠的原生插槽。该夹具中带绘制拆除的中位数为 1.035 ms，最大值为 6.597 ms。另一项 100,000 节点存储图基准移除 10,000 个连续端点，拓扑访问为零；它不含原生工厂与渲染工作。

原始交互测量数据：`interaction-results.txt`。

## 正确性覆盖与限制

0.5.0 的机器接口夹具将一个启用的、按水过滤的生产端点接入 100,000 节点网络。预热缓存后，100,000 次远端存入/提取对在 Unity/Mono 下平均每次操作 343.3 ns。全部 200,000 次操作都保持拓扑访问计数器与储液罐索引版本不变。该夹具还检查远端物品预留、混装物品拒绝、原生输入缓存守恒与全局禁用。该测量将库存 API 工作与生产 tick、渲染和建造隔离开。

两个套件均通过。覆盖范围包括类型/容量拒绝、过滤提取、空网络流体更换、确定性拆分、兼容/不兼容合并、二进制存档恢复、20,000 次随机操作与独立连通性及库存对照基准的比对、以及拓扑变更期间的并发 I/O。运行时覆盖包括缓存/原生工厂 I/O、实际货物缺失、普通传送带回归检查、原生路径拼接、闭环、接头、改道、拆除/退还记账、传送带 ID 回收、储液罐更新、物流塔更新与分流器拒绝。

运行时检查还覆盖物流塔接口上管道流体与普通传送带的同步传输、储液罐/物流塔接口的两种连接顺序、13 接口任意角度管道接头、幂等反向连接、待建节点完成与附加连接序列化。预览条件检查演练带高度差与锐角的管道连接，同时覆盖物理碰撞拒绝与普通传送带规则。

断边夹具覆盖原生支持连接与附加连接、保留的端点与总容量、环绕环路的替代路线、桥接拆分、流体与增产点守恒、重复反向切割以及断开边的恢复。带高度差接头的条件检查保留物理碰撞拒绝。

几何检查覆盖度数 0、1、2、3、13 与 100，一个凸三维转角、有限顶点与朝外的面绕序。共线段共享连续玻璃表面。实时空间区块渲染与由库存驱动的流体外观变化在游戏运行时中执行；库存变化使用缓存的外层网格选择材质。图库以生产材质截取六种程序化形状。量化大规模网络渲染与接头网格生成开销需要专门的计时夹具。

独立的场景测试夹具加载一个全新的沙盒星球，并通过工厂 API 创建 45 个管道实体、43 个原生 Mk.I 传送带实体和两个原生储液罐。九次离屏游戏相机截图展示成对的直管、弯头、T 形接头与带高度差布局，含真实地形与光照、空管/充水对比以及孤立的圆端节点。第二个 69 节点场景截取直管、弯头、斜 Y、T 形、竖直入口与八接口形态，并使用相同的空/满相机视角。原生渲染器创建、管道传送带网格抑制与生产管道绘制一起运行。截图会检查像素非均匀性并进行目视检查。这些夹具在小规模布局上验证材质外观、几何与原生渲染集成。

其他夹具截取成对的蛇形、立交与单/多环结构，外加一个 3 单位立方体框架。该立方体包含 32 个节点与 36 条边，有五个独立环。每个节点在存入后立即暴露相同的 1,280 单位库存，在某一节点提取后库存为零。立方体截图包含匹配的空/满视角，以及另外两个空管视角。

加载的立方体夹具在激活原生碰撞体的情况下执行原版 `BuildTool_Path.CheckBuildConditions`：传送带与管道都接受空旷地形，并拒绝实体储物箱阻挡。切断立方体的一条边会保留替代连通性；隔离一个角会保留全部 32 个实体，并将 1,280 单位水分配为 40 与 1,240。重新连接会将总库存恢复为 1,280 单位。另一张截图显示切断一条边后的可见缺口。

大型运行时夹具包含原生实体/传送带池，每条货运路径 100 个管段，并使用合成几何。小型建造夹具在抑制渲染回调的情况下执行原版连接与几何变更。平行产线夹具验证完整的原生存档重载。蓝图放置、鼠标驱动的可视化交互、第三方运输补丁与多人游戏需要专门的验证夹具。

原始结果：`runtime-results.txt` 和 `core-results.txt`。复现命令见项目 README。
